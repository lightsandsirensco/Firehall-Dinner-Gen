# Daily return loop — dinner only

**Status:** Implemented  
**Governed by:** [feature-filter.md](./feature-filter.md) (Product Constitution)

Natural reasons to open Firehall Meals before dinner (no artificial engagement):

| Reason | When Home surfaces it |
|--------|------------------------|
| Tonight's meal unset | Primary next action + checklist |
| Crew vote open | Primary if voting; else "Also open tonight" |
| Shopping needed | Primary if shopping; else secondary loop |
| Continue cooking | Primary when cook was started on tonight's meal |
| Start / open recipe | When dinner is locked |
| Favorites | Decide phase — saved meals ready |
| Suggested | Decide phase — recent/saved cook-again list |

## Why return tomorrow

The slate resets every shift. Dinner isn't decided again until someone opens Home and locks it. Open votes and shopping lists create unfinished business that only resolves by coming back. Favorites/suggestions only appear when dinner still isn't locked — they speed the same job, they don't invent a new one.
